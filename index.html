Protection layers

Everything you need to protect a script

Every build runs through a configurable pipeline of independent passes — mix and match per preset.

Control-Flow Flattening

Rebuilds function logic into an opaque state-machine dispatcher, destroying the original control-flow graph.

String Encryption

Every string literal is encrypted and decrypted on-demand at runtime — never sitting in plaintext in the output.

Bytecode Virtualization

Compiles hot paths into a custom instruction set, interpreted by a unique VM generated per build.

Anti-Tamper Checksums

Continuously verifies the integrity of the compiled chunk and reacts if it's been patched — see LSV_CRASH.

Identifier Renaming

Strips every meaningful variable, function and upvalue name and replaces it with noise, breaking static readability.

Dead Code & Opaque Predicates

Injects unreachable branches and always-true/false conditions that confuse decompilers and static analysis.

Constant Array Encoding

Numbers and constants are split, encoded, and reconstructed through arithmetic at runtime.

Per-Build Watermarking

Every compiled script embeds an invisible, unique fingerprint so leaks can be traced back to a build.

FAQ

Frequently asked questions

What Lua versions does LSV support?

Lua 5.1, 5.2, 5.3, and Luau (Roblox's dialect). Pick a target with --target on the CLI or in the Dashboard uploader.

Can I self-host the obfuscator?

Yes — Enterprise plans include on-prem and self-hosted build options with a dedicated compiler image.

Will obfuscation affect script performance?

Minify through Strong have negligible to low overhead. Virtualized trades some performance for maximum protection — use the LSV_NO_VIRTUALIZE() macro to exempt hot loops. See the Macros docs.

What happens if I exceed my monthly quota?

Extra jobs are queued until your quota resets, or you can upgrade instantly to keep going without a queue.

Do you store my source code?

Scripts are processed in memory for the duration of the build and are not retained afterward.

Can I switch plans anytime?

Yes, upgrades and downgrades are prorated and take effect immediately.

Getting Started

Introduction

LSV is a compiler-based obfuscator for Lua and Luau. It takes a script you'd normally ship as-is and runs it through a configurable pipeline — renaming, string encryption, control-flow flattening, dead-code injection, constant encoding, and an optional full bytecode virtual machine — producing a functionally identical script that's dramatically harder to read, diff, or decompile.

Supported dialects

  • Lua 5.1, 5.2, 5.3
  • Luau (Roblox's dialect), including typed syntax

The pipeline

Every build runs the same four stages: parse your source into an AST, transform it through the passes your chosen preset enables, expand any LSV macros it finds into real logic, then emit the protected Lua output.

New here? Continue to Quick Start to obfuscate your first script in under a minute.

Quick Start

You can obfuscate a script from the CLI, or by dropping a file into the Dashboard tab's uploader — no CLI required.

1. Install the CLI

bash
npm install -g lsv-cli
# or
curl -fsSL https://example.com/install.sh | sh

2. Set your API key

Grab your key from the Dashboard tab.

bash
export LSV_API_KEY="lsv_live_xxxxxxxxxxxxxxxx"

3. Obfuscate a script

Guides

Macros

LSV macros are special call-style directives recognized by the compiler's preprocessor. You write them directly in your Lua source as ordinary-looking function calls — LSV strips, rewrites, or injects real behavior into them at obfuscation time. When you run the raw, unobfuscated source directly during development, they safely no-op instead of erroring.

Note — Macros are matched syntactically before compilation, not real functions. Don't wrap them in pcall or reassign them to a variable — call them directly, exactly as shown below.
MacroCategoryReturnsSummary
LSV_CRASHAnti-TamperneverHalts execution via an obfuscated panic routine
LSV_OBFUSCATEDCompilerboolean / stringDetects whether you're running the compiled build
LSV_NO_VIRTUALIZEPerformancevoidExcludes the enclosing function from VM virtualization
LSV_PRECHECKSecuritybooleanRuns an environment integrity sweep before your script runs

LSV_CRASH

Anti-Tamper

Halts execution through an obfuscated, build-unique panic routine — call it wherever a tamper or integrity check fails.

LSV_CRASH(message?: string, delaySeconds?: number) → never
ParameterTypeDefaultDescription
messagestringnilOptional custom text baked into the compiled panic routine.
delaySecondsnumber0Waits before triggering, so the crash can't be traced back to the exact check that caused it.
license.lua
-- Halt immediately if the license check fails
local function verifyLicense(key)
    if not key or #key ~= 32 then
        LSV_CRASH()
    end
end

-- Custom panic message with a delay, so it can't be
-- correlated back to this exact check
if workspace:GetAttribute("Sandboxed") == true then
    LSV_CRASH("unauthorized environment", 3)
end
Note — The panic routine is re-randomized per build (error vs. corrupted state vs. infinite yield), so a patch written against one build won't transfer to the next. LSV_PRECHECK's strict mode calls this internally on failure.

LSV_OBFUSCATED

Compiler Directive

A zero-cost marker you can query at runtime to detect whether the currently executing script is the compiled, protected build or raw dev source.

LSV_OBFUSCATED(query?: "bool" | "build" | "version") → boolean | string
ParameterTypeDefaultDescription
querystring"bool""bool" returns true/false. "build" returns the build fingerprint. "version" returns the LSV compiler version used.
main.lua
if LSV_OBFUSCATED() then
    -- only true in the compiled, protected build
    initAntiTamper()
else
    print("[dev] running raw source — remember to build before shipping")
end

-- stamp logs with the build fingerprint in production
local build = LSV_OBFUSCATED("build")
if build then
    logger:info(("running build %s"):format(build))
end
Note — Safe to leave in shared or open-sourced code — it's an ordinary function call with no effect until the file is actually run through LSV.

LSV_NO_VIRTUALIZE

Performance

Excludes the enclosing function (or the whole file, if placed at the top) from bytecode virtualization — it still gets every other pass, but runs as native Lua instead of inside LSV's VM.

LSV_NO_VIRTUALIZE() → void
Placement — Must be the first statement in the function body it scopes. As the first statement of the whole file, it scopes the entire chunk.
render.lua
local function renderStep(dt)
    LSV_NO_VIRTUALIZE() -- must be the function's first statement

    for _, part in ipairs(movingParts) do
        part.CFrame = part.CFrame * CFrame.new(0, FALL_SPEED * dt, 0)
    end
end
Note — Only affects the Virtualized preset. It's a harmless no-op on Minify/Weak/Medium/Strong, since those presets don't virtualize to begin with.

LSV_PRECHECK

Security

Runs LSV's environment integrity sweep before the rest of the chunk executes — detects common static/dynamic analysis environments and verifies the compiled chunk wasn't modified after the build.

LSV_PRECHECK(options?: table) → boolean
OptionTypeDefaultDescription
mode"strict" | "silent""strict"strict calls LSV_CRASH() internally on failure. silent just returns false so you can branch yourself.
timeoutnumber2Seconds allowed for async environment checks before giving up.
main.lua
-- strict mode: halts internally if any check fails
LSV_PRECHECK({ mode = "strict", timeout = 2 })

local Players = game:GetService("Players")
-- ...rest of your protected script

-- silent mode: handle the failure yourself
local passed = LSV_PRECHECK({ mode = "silent" })
if not passed then
    return
end
Note — strict mode composes with LSV_CRASH — see that macro above for what the failure path looks like downstream.

CLI Reference

Flags accepted by lsv build.

FlagDescription
-o, --out <path>Output file path. Defaults to <name>.protected.lua.
--preset <name>minify | weak | medium | strong | virtualized. Default: medium.
--target <dialect>lua51 | lua52 | lua53 | luau. Default: luau.
--watermark <id>Embeds a custom build fingerprint, surfaced via LSV_OBFUSCATED("build").
